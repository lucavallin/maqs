# Swift package, sub-project 1: skeleton and `MaqsCore` — design

**Date:** 2026-10-16 · **Status:** approved in conversation; spec under review
**Brief:** `docs/BRIEF.md` § Phase 4 · **Builds on:** ADR 0003 (platforms), 0007 (base pack), 0008 (online opt-out, privacy), 0012 (manifest, compatibility rule), 0013 (what a client may assume about a release)

## Scope

Phase 4 is decomposed into four sub-projects, each with its own spec, plan and execution, in this order:

1. **Skeleton and `MaqsCore`** (this spec): `Package.swift`, `swift.yml`, fixtures, manifest and `sources.json` clients, region discovery, downloads, install, storage, observable state.
2. **`MaqsTerrain`**: PMTiles reader, terrarium decoding, sampling, profiles, online tiles with a bounded LRU.
3. **`MaqsData`**: SQLite readers for trails, places and curvature, and the shared corner math (ADR 0008).
4. **`MaqsUI` and `Examples/MaqsDemo`**: MapLibre view, runtime style assembly, the offline-switching ADR, bundled glyphs and sprite, attribution view, overlays, demo app.

The package is tagged `v0.1.0` only after sub-project 4. Until then nothing depends on it.

## Decisions (approved 2026-10-16)

1. **Discovery is data and observable state only.** The package fetches the latest manifest, caches it and exposes a catalog; apps draw their own region list. No region picker view, now or in `MaqsUI`.
2. **Base packs both ways.** An app can register a base pack it bundles itself (ADR 0007) and `MaqsCore` can also download a base pack listed in the manifest. A base pack is a pack with one layer and no clip; it shares the region code path.
3. **The online opt-out is an app-side setting**, `onlineTiles`, in the `MaqsCore` configuration. `false` means `MaqsUI` and `MaqsTerrain` never request a tile or a DEM online, so no coordinate leaves the device. Fetching `manifest.json` and `sources.json` stays allowed in both modes, since those requests carry no position; an app that wants no network at all never calls refresh. This closes the question ADR 0012 left open: an empty `sources.json` is not the opt-out and the schema keeps requiring one source per layer.
4. **Fixtures are committed.** `Tests/Fixtures/` holds the `test` region's outputs and is the only place binary data may live in git, capped at 8 MB, regenerated by one script. `swift test` works from a clean checkout with no Python. CLAUDE.md's "a `.pmtiles` or `.sqlite` in a commit is a mistake" gets this one exception.
5. **One entry point over small internal parts.** A public `actor Maqs` owns the manifest client, the sources client, the pack store and the download manager, all `internal`. `MaqsTerrain` and `MaqsData` take plain file URLs and values, never `MaqsCore` types, so products stay independent (Swift package rule 1).

## Success criteria

- `swift build -Xswiftc -warnings-as-errors` and `swift test` pass on macOS from a clean checkout; `xcodebuild test` passes on an iOS Simulator; both run in `swift.yml` on pushes and PRs that touch the package, and not on pipeline-only or docs-only changes.
- With the fixture manifest served by a stub, an app that asked for `[.trails, .places]` sees the `test` region with those two layers, their bytes and schema versions, and nothing about basemap or terrain; a manifest offering only `layer_schema_version` 2 for trails shows that layer as `unreadable`; an unknown `manifest_version` is a typed error and the previous catalog stays.
- `install(.region("test"))` against the stub downloads every file of the chosen entries, verifies each SHA-256, and only then makes the pack visible; a wrong SHA-256 installs nothing and reports `DownloadError.checksumMismatch`; a cancel leaves no file a reader can find; `remove` deletes the pack directory; a changed SHA-256 in a newer manifest shows `updateAvailable`.
- A bundled base pack registered from a file URL appears as an installed pack without any download.
- `onlineTiles == false` hides the online sources entirely.
- Every public symbol has a DocC comment; `MaqsCore` imports no third-party module and no SQLite or MapLibre.
- ADR 0014 records the decisions above and the facts verified during planning, with dates.

## Package layout

```
Package.swift
Sources/MaqsCore/                      # the product
Sources/MaqsCore/Resources/sources.json   # byte-identical copy of config/sources.json (CI diff)
Sources/MaqsTestSupport/               # test-only library: fixture URLs, stub URLProtocol, temp directories
Tests/MaqsCoreTests/<Type>Tests.swift
Tests/Fixtures/                        # the committed data (see below); MaqsTestSupport copies it as resources
scripts/update-fixtures.sh             # regenerates Tests/Fixtures and the bundled sources.json copy
.github/workflows/swift.yml
```

`Package.swift`: `swift-tools-version` 6.2 if the installed toolchain accepts it (Xcode 27, Swift 6.4), platforms `.iOS(.v18)` and `.macOS(.v15)`, `swiftLanguageModes: [.v6]`. Products and targets in this sub-project: library `MaqsCore`; target `MaqsTestSupport` (not a product, depends on `MaqsCore`); test target `MaqsCoreTests` (depends on both). Terrain, Data and UI targets are added by their sub-projects; no stubs. No MapLibre dependency yet. No `unsafeFlags` anywhere: a package that uses them cannot be consumed as a dependency. Warnings as errors: the plan checks whether the toolchain's SwiftPM offers a safe per-target setting (`SwiftSetting.treatAllWarnings(as: .error)`, Swift 6.2's warning-control proposal); if it does, use it; if not, the CI flag `-Xswiftc -warnings-as-errors` is the mechanism and `xcodebuild` gets `SWIFT_TREAT_WARNINGS_AS_ERRORS=YES`.

SwiftPM resources must live inside a target directory, which is why the fixtures reach the tests through `MaqsTestSupport`. The spec keeps one copy of the data in git: `Tests/Fixtures/` is the committed source, and `MaqsTestSupport` declares that directory as its resource path with `path:` pointing outside its own folder only if SwiftPM allows it; otherwise `Sources/MaqsTestSupport/Fixtures/` is the committed location and `Tests/Fixtures/` does not exist. The plan settles which, by trying it; the rest of this document says `Tests/Fixtures/` for the location, whichever it ends up being.

## `swift.yml`

- Triggers: `push` and `pull_request` with `paths`: `Package.swift`, `Package.resolved`, `Sources/**`, `Tests/**`, `scripts/update-fixtures.sh`, `config/sources.json`, `.github/workflows/swift.yml`.
- `permissions: contents: read`, `concurrency` per ref with `cancel-in-progress: true` (CI only; nothing publishes).
- Job `macos`: `macos-latest`, `swift build -Xswiftc -warnings-as-errors`, `swift test`.
- Job `ios-simulator`: `macos-latest`, `xcodebuild -scheme Maqs-Package -destination 'platform=iOS Simulator,name=<a simulator the runner image has>' test`; the plan reads the runner image's simulator list and pins a name that exists there, recorded in the ADR. Output grepped for `": error:"` and the `Test run with N tests` line, per CLAUDE.md.
- Job `guards` on `ubuntu-24.04` (cheap, no macOS minutes): `import MapLibre` appears only under `Sources/MaqsUI/`; `cmp config/sources.json Sources/MaqsCore/Resources/sources.json`; `du -sk Tests/Fixtures` under the cap; `git ls-files` shows no `.pmtiles`, `.sqlite` or `.pbf` outside `Tests/Fixtures/`.
- Only `actions/checkout@v7` (pinned major tag like the other workflows); `pipeline/tests/test_workflows.py` extends its pin and permission checks to `swift.yml`.

## Fixtures

`scripts/update-fixtures.sh` runs, from the repo root:

```
(cd pipeline && uv run maqs build --region test && uv run maqs build --region base \
  && uv run maqs manifest --release data-ci --regions test)
```

then copies `dist/test/*`, `dist/base/*` and `dist/manifest.json` into `Tests/Fixtures/`, copies `config/sources.json` to `Sources/MaqsCore/Resources/sources.json`, and fails if the fixture total exceeds 8 MB. Today the `test` region is about 3.4 MB and the `base-triveneto` pack about 13 MB, which breaks the cap; the script therefore copies only the base pack's `build-report.json`, not the 13 MB file, and the base-pack tests use the `test` region's basemap file under the base pack's name. The fixture manifest is the real `data-ci` manifest, so its `url`s name `data-ci`; the stub `URLProtocol` serves them from the fixture directory by file name.

Hand-built files beside the generated ones: `invalid/` holds one JSON file per invalid manifest shape (missing field, wrong type, `manifest_version: 2`, `http://` URL, foreign host, unknown layer key, unknown field, entry with unknown `role`), each named after what it proves.

## Public API

All types `public`, `Sendable`, DocC-documented. Names follow the Swift API Design Guidelines; the plan may refine spellings but not shapes.

```swift
public enum Layer: String, Codable, Sendable, CaseIterable {
    case basemap, terrain, terrainHD = "terrain-hd", trails, places, curvature
}

public enum PackID: Hashable, Sendable, Codable {
    case region(String)
    case base(String)
}

public struct MaqsConfiguration: Sendable {
    public var layers: Set<Layer>
    public var userAgent: String                      // required; the package appends "Maqs/<version>"
    public var onlineTiles: Bool = true               // ADR 0008 opt-out
    public var backgroundSessionIdentifier: String?   // nil: foreground URLSession
    public var manifestURL: URL                       // default: .../releases/latest/download/manifest.json
    public var sourcesURL: URL                        // default: raw main config/sources.json
    public var storageDirectory: URL?                 // default: Application Support/Maqs
    public var catalogMaxAge: Duration = .seconds(86_400)
    public init(layers: Set<Layer>, userAgent: String)
}

public actor Maqs {
    public init(configuration: MaqsConfiguration) throws
    @MainActor public let state: MaqsState

    public enum RefreshPolicy: Sendable { case ifStale, always }
    public func refreshCatalog(policy: RefreshPolicy = .ifStale) async throws -> Catalog

    public func install(_ pack: PackID) async throws
    public func cancelInstall(_ pack: PackID) async
    public func remove(_ pack: PackID) async throws
    public func registerBundledBasePack(id: String, basemap url: URL) async throws
    public func installedPack(_ pack: PackID) async -> InstalledPack?
    public func diskUsage() async throws -> DiskUsage

    public var onlineSources: OnlineSources? { get async }   // nil when onlineTiles == false
    public func refreshOnlineSources(policy: RefreshPolicy = .ifStale) async throws

    #if os(iOS)
    public nonisolated func handleEventsForBackgroundURLSession(identifier: String,
                                                                completionHandler: @escaping @Sendable () -> Void)
    #endif
}

@MainActor @Observable public final class MaqsState {
    public private(set) var catalog: Catalog?
    public private(set) var packs: [PackID: PackState]
    public private(set) var lastRefreshError: MaqsError?
}

public struct Catalog: Sendable {
    public let release: String            // "data-2026-10"
    public let createdAt: Date
    public let fetchedAt: Date
    public let attribution: [Attribution]
    public let regions: [PackSummary]
    public let basePacks: [PackSummary]
}

public struct PackSummary: Sendable, Identifiable {
    public let id: PackID
    public let names: [String: String]    // language code → name; base packs: [:]
    public let bbox: BoundingBox?         // nil for base packs
    public let layers: [Layer: LayerAvailability]   // only the configured layers the pack offers
    public let totalBytes: Int64          // sum over available layers
    public let status: PackStatus
}

public enum LayerAvailability: Sendable {
    case available(bytes: Int64, schemaVersion: Int, dataDate: Date, osmTimestamp: Date?)
    case unreadable(offeredVersions: [Int])   // every version is newer than this package reads
}

public enum PackStatus: Sendable {
    case notInstalled
    case installed(release: String)
    case updateAvailable(release: String, bytes: Int64)   // any installed layer's sha256 differs
    case partiallyInstalled(missing: Set<Layer>)          // the app's layer set grew since install
}

public enum PackState: Sendable {
    case notInstalled
    case downloading(DownloadProgress)   // per pack, summed over its files
    case verifying
    case installed(InstalledPack)
    case failed(MaqsError)
}

public struct DownloadProgress: Sendable, Equatable {
    public let bytesReceived: Int64
    public let totalBytes: Int64
}

public struct InstalledPack: Sendable {
    public let id: PackID
    public let release: String
    public let files: [Layer: [InstalledFile]]   // trails and places: two files (sqlite + overlay)
    public let bundled: Bool                      // registered by the app, not downloaded
}

public struct InstalledFile: Sendable {
    public let url: URL
    public let role: String?          // manifest `role` when present (e.g. "overlay")
    public let schemaVersion: Int
    public let sha256: String
    public let bytes: Int64
    public let dataDate: Date
}

public struct OnlineSources: Sendable {
    public let version: Int
    public let basemap: [TileSource]
    public let terrain: [TileSource]
}

public struct TileSource: Sendable {   // one entry of sources.json, verbatim
    public let id: String, provider: String
    public let tiles: URL?, tilejson: URL?
    public let schema: String, format: String
    public let tileSize: Int?, minZoom: Int, maxZoom: Int
    public let attribution: [String]
}

public enum MaqsError: Error, LocalizedError, Sendable {
    case manifest(ManifestError)
    case download(DownloadError)
    case storage(StorageError)
    case sources(SourcesError)
}
```

`ManifestError`: `unsupportedVersion(Int)`, `invalid(String)` (one message per Codable failure, no raw JSON), `insecureURL(String)`, `foreignHost(String)`, `network(statusCode: Int?)`, `rateLimited`. `DownloadError`: `checksumMismatch(file: String)`, `sizeMismatch(file:)`, `network(statusCode:)`, `cancelled`, `layerUnreadable(Layer)`, `notInCatalog(PackID)`. `StorageError`: `cannotCreateDirectory`, `writeFailed(String)`, `corruptRecord(PackID)`. `SourcesError`: `unsupportedVersion(Int)`, `invalid(String)`, `network(statusCode:)`. Every `errorDescription` says what to do ("Update the app to read this layer", "Try again later", "Free disk space").

The package's own GitHub URLs are defaults in the configuration. They are not provider URLs; the brief's rule concerns tile and DEM providers, which stay in `sources.json`.

## Discovery

`refreshCatalog(policy:)`:

1. `.ifStale` returns the cached catalog without a request when the cached manifest's fetch date is younger than `catalogMaxAge`. `.always` always requests. The package never fetches on its own timer.
2. The request is a GET to `manifestURL` with `User-Agent` and, when a cached ETag exists, `If-None-Match`. The session has HTTP caching on and never sends `Cache-Control: no-cache`. A 304 refreshes the fetch date and keeps the cached manifest. A 429 is `ManifestError.rateLimited`; 5xx and transport errors are `.network`. Nothing is retried inside the call; the cached catalog stays and `state.lastRefreshError` is set.
3. The body is parsed with strict `Codable` (`manifest_version` first; an unknown value is `.unsupportedVersion` and the cached manifest stays). Every entry `url` must be `https` and have the same host as `manifestURL`; otherwise the whole manifest is rejected (`.insecureURL`, `.foreignHost`), because a manifest pointing elsewhere is not ours. Unknown fields, unknown layer keys and entries with an unknown `role` are ignored, as `data-format.md` says.
4. The compatibility rule is applied per pack and layer: the readable schema versions per layer are a table in `MaqsCore` (today `[1]` for every layer); the first entry with a readable version wins; none readable is `unreadable(offeredVersions:)`.
5. The catalog is derived for the configured layers only and `state.catalog` is replaced. The manifest, ETag and fetch date are written to storage atomically so the next launch starts from them.

`PackStatus` is computed from the catalog and `pack.json`: `installed` when every configured layer's installed SHA-256 equals the chosen entry's; `updateAvailable` when any differs (the bytes are the sum of the layers that changed); `partiallyInstalled` when a configured layer has no installed file but the catalog offers it; otherwise `notInstalled`. A bundled base pack is always `installed` and never `updateAvailable`, because the app owns that file.

## Downloads and install

Storage, under `storageDirectory` (default `Application Support/Maqs/`), with `isExcludedFromBackup` set on the root directory at creation:

```
Maqs/
  manifest.json  manifest.meta.json     # ETag, fetchedAt
  sources.json   sources.meta.json
  packs/<pack-id>/pack.json             # InstalledPack record; readers see only files it names
  packs/<pack-id>/<layer>/<file>
  downloads/<task-id>                   # in flight; never named by pack.json
```

`<pack-id>` is `region-<id>` or `base-<id>`.

Install of pack P:

1. The catalog must list P with every configured layer `available`; an `unreadable` layer fails before any download (`.layerUnreadable`); a pack not in the catalog fails (`.notInCatalog`). Layers already installed with the same SHA-256 are skipped.
2. One download task per file, in a `URLSession` built from `backgroundSessionIdentifier` when set (iOS) or a default configuration otherwise, with the User-Agent and HTTP caching on. At most 2 files download concurrently per pack and one pack installs at a time; further installs queue. `PackState.downloading(DownloadProgress)` sums bytes over the pack's files.
3. A finished download is moved from the session's temporary location into `downloads/`, its size compared to the manifest's `bytes` and its SHA-256 computed with CryptoKit in streaming reads. Mismatch: the file is deleted and the pack fails with `.checksumMismatch` or `.sizeMismatch`; nothing already installed changes.
4. When every file verifies, each is moved into `packs/<pack-id>/<layer>/` (replacing the old file of that layer, if any), and `pack.json` is rewritten last, by writing a sibling and renaming over it. A crash between steps leaves the old `pack.json` naming the old files, which are untouched until the rename, or the new `pack.json` naming files that all exist. Files left behind in `downloads/` or orphaned by a crash are swept on the next launch.
5. Readers that hold an old file open keep it until they reopen (POSIX unlink semantics); `installedPack(_:)` returns the new record immediately.

Cancel: tasks are cancelled with `cancel(byProducingResumeData:)`, the resume data is kept in `downloads/`, the pack returns to its previous state, and a later `install` resumes. Resumed bytes are never trusted: step 3 hashes the whole file. Remove: the pack directory is deleted, in-flight tasks cancelled, `pack.json` removed first so no reader finds a half-deleted pack. A bundled base pack is not deleted by `remove`, only unregistered.

Background session (iOS): the app forwards `application(_:handleEventsForBackgroundURLSession:completionHandler:)` to `Maqs.handleEventsForBackgroundURLSession`; on relaunch the package recreates the session with the same identifier and the system reconnects the tasks. Without an identifier, downloads live as long as the app runs. The plan verifies the exact `URLSession` behaviour against current documentation (Context7, `ios-networking`, `background-processing` skills) before implementation and records what it found in ADR 0014.

Rate limits: a 429 from `github.com` fails the pack with `.network(statusCode: 429)`; the package does not retry. `releases/download` URLs redirect to `objects.githubusercontent.com`; the redirect is followed by `URLSession`, and the host check applies to the URL in the manifest, not the redirect target.

## `sources.json`

Same client pattern as the manifest: `refreshOnlineSources(policy:)`, GET with `If-None-Match`, 304 keeps the cache, strict parse, `sources_version` unknown is `SourcesError.unsupportedVersion` and the last good copy stays. Resolution order: cached file, then the bundled copy in `Sources/MaqsCore/Resources/sources.json`. `onlineSources` returns the parsed values, or `nil` when `onlineTiles == false`; the opt-out is applied in one place so `MaqsUI` and `MaqsTerrain` cannot see a URL they must not use. `MaqsTerrain` and `MaqsUI` receive `TileSource` values from the app and never import `MaqsCore`.

## Observability

`os.Logger(subsystem: "com.lucavallin.maqs", category: "core")`: one line per refresh (outcome, status code, bytes), per install step and per failure, at `info`/`error`. No URL query strings, no file contents, no coordinates (Core has none). Failures surface in `MaqsState` (`lastRefreshError`, `PackState.failed`) where the app shows them; the demo app (sub-project 4) displays both. No alerting applies to a client library; the one production signal is the manifest endpoint, covered by `build-maps.yml`.

## Tests (`Tests/MaqsCoreTests`, Swift Testing)

Stubbed `URLProtocol` from `MaqsTestSupport` serving fixture files and scripted responses; a fresh temporary `storageDirectory` per test; no live network; foreground session configuration in tests.

- `ManifestTests`: parses the fixture manifest; one test per `invalid/` file naming the rejected shape; `manifest_version: 2` is `.unsupportedVersion`; unknown field, unknown layer key and unknown `role` are ignored.
- `CompatibilityTests`: highest readable version chosen; readable version below an unreadable one chosen; none readable is `unreadable(offeredVersions:)`; the readable-version table is what the rule reads.
- `CatalogTests`: only configured layers appear; `totalBytes`; `notInstalled`, `installed`, `updateAvailable` and `partiallyInstalled` from a `pack.json` and a manifest; base packs listed with no bbox; names dictionary.
- `RefreshTests`: `.ifStale` makes no request when fresh; `.always` sends `If-None-Match`; 304 keeps the catalog; 429 sets `lastRefreshError` and keeps the catalog; a rejected manifest keeps the previous one; the manifest and ETag survive a new `Maqs` instance over the same directory.
- `InstallTests`: success installs every file and writes `pack.json` last; checksum mismatch installs nothing and deletes the download; size mismatch likewise; cancel leaves nothing visible and resumes; remove deletes the directory and the state; update replaces only changed layers; `unreadable` layer refuses before any request; two files per version for trails and places; a pack not in the catalog fails; concurrent `install` of the same pack is one install.
- `BasePackTests`: register a bundled file; it is `installed` and never `updateAvailable`; `remove` unregisters without deleting; downloading a manifest base pack works like a region.
- `SourcesTests`: bundled fallback when nothing is cached; cached copy preferred; strict parse and `unsupportedVersion`; `onlineTiles == false` returns `nil`.
- `StorageTests`: root directory excluded from backup; orphan sweep on launch; corrupt `pack.json` is `StorageError.corruptRecord` and the pack reads as `notInstalled`.
- `ConfigurationTests`: User-Agent header carries the app string plus the package token on every request.

`pipeline/tests/test_workflows.py` gains `swift.yml` in its pin and permission checks.

## Out of scope

`MaqsTerrain`, `MaqsData`, `MaqsUI`, the demo app, glyphs and sprite, any view, the package's first tag, retries and scheduling inside the package, a second manifest host, delta or partial-file updates, migration of an older storage layout (there is none).

## Risks

- `URLSession` background behaviour cannot be unit-tested on macOS; it is verified on the simulator leg and by hand in the demo (sub-project 4).
- The fixture cap (8 MB) excludes the real base pack; the base-pack tests use the `test` basemap under another name, which exercises the code path but not the real file.
- If SwiftPM rejects a resource path outside the target, the committed fixture location moves under `Sources/MaqsTestSupport/`; the guards and the script follow.
- GitHub's `releases/latest/download` redirect may not return an ETag; then every `.always` refresh downloads the whole manifest (about 10 KB), which is acceptable, and the ADR records it.

# Architecture

## Pipeline (`pipeline/`)

A thin Python orchestrator around pinned CLIs. One map provider, VersaTiles, supplies every tile online and offline ([ADR 0004](decisions.md)). Geofabrik supplies the OSM data for the data layers (trails, places, curvature).

- **Entry point:** `uv run maqs build --region <id>|all|base [--layers …] [--force] [--dist DIR] [--cache DIR]`, plus `maqs regions [--json]`, `maqs fetch --extract NAME [--cache DIR]`, `maqs check-tools`, `maqs check-config [--manifest PATH]`, `maqs manifest --release TAG [--regions IDS] [--previous PATH] [--dist DIR] [--out PATH]`, `maqs previous-manifest --releases PATH --release TAG` and `maqs release-check --dist DIR --manifest PATH [--previous PATH] [--notes PATH]`, run from `pipeline/`. `--layers` defaults to `basemap,terrain,trails,places,curvature`; `terrain-hd` is opt-in. Whatever order `--layers` names them in, the steps of a region run in the fixed order basemap, terrain, terrain-hd, trails, places, curvature. `--region all` builds every region, the `test` fixture included; `--region base` builds every base pack as one target: one step per pack (`base-<pack>`), all writing to `dist/base/` with one build report. A usage error exits 2, and so does a schema violation `check-config` finds; a tool, configuration, build, download, manifest or release-check failure exits 1. `maqs regions --json` prints the regions (id, fixture flag, names, bbox, Geofabrik extract), the base packs and the list of extracts, for the release workflow to plan from.
- **Configuration:** `config/regions.yaml`, loaded and checked by `maqs/config.py`. Top level: `schema_version` (1), `hd_max_zoom` (default 13), `curvature` (optional: `highways`, the road classes the curvature layer reads, and `exclude_surfaces`, the surfaces it skips; both lists of strings, defaulting to the lists the file sets today), `base_packs` and `regions` (both lists of mappings). A malformed file, YAML syntax included, is a configuration error (exit 1) that names what is wrong. A region has an `id` (lowercase kebab-case; `all` and `base` are reserved for `--region`), `name` with `it` and `en`, a `bbox` (`[lon_min, lat_min, lon_max, lat_max]`, not crossing the antimeridian), and optionally `bbox_border` (tiles of margin around the bbox at every zoom, an integer ≥ 0, default 1), `fixture` (`true` or `false`; a fixture is built for tests and CI only), `hd_max_zoom` (≥ 13), `osm.geofabrik` (the Geofabrik extract its data layers read; a data step fails without it), `clip.admin` (OSM relation ids the data layers are cut by; without it they are cut by the bbox), `trails.sources` (trail sources in priority order, at least one; only `osm` exists, and it is the default) and `expect` (row-count ranges: `trails`, `places` and `curvature_segments`, each `[min, max]` with 0 ≤ min ≤ max). A base pack has an `id` (same rules), the `regions` it covers (never a fixture) and a `max_zoom` (0–14, default 10). A region is the smallest unit a pack is cut at, and regions can be anywhere in the world ([ADR 0009](decisions.md)).
- **Steps:** `maqs/steps/` for the runner and the tile layers, `maqs/trails/`, `maqs/places/` and `maqs/curvature/` for the data layers. Each step implements `outputs(ctx)` (its files, named by `output_name` in `maqs/layers.py`, which also holds each layer's `layer_schema_version`), `expectation(ctx, output)` (what one output must look like: a tile `Expectation` or a `SqliteExpectation`) and `build(ctx)`, which returns a `StepOutcome`: the command to report and the anomalies it found. Region-scoped steps get their region from `BuildContext.require_region()`, which raises for the base-pack target. The runner (`steps/base.py`) skips a step whose outputs all exist unless `--force` is given. It then validates every output, skipped ones included, so a truncated file from a crashed run is caught and reported with a `--force` hint, and records each output's layer, `layer_schema_version` and the run's date (`BuildContext.data_date`, one value per run) for the manifest. It keeps the first 1,000 anomalies of a step and counts all of them, in total and per kind. A tool failure, a missing tool, a filesystem error or a failed check marks the step failed in the report and the build goes on to the next region (`--region all`); any other exception is a bug and stops the build.
- **Tools:** `maqs/tools.py` is the only place a subprocess starts: no shell, the exact command logged, a non-zero exit raised as `ToolError`. `tools.run` captures a tool's output and puts the tail of its stderr in the `ToolError` instead of streaming it live, a deliberate simplification: CI logs stay short, at the cost of no progress output during a long local extract. Version pins live in `PINS` and in `pipeline/bootstrap.sh`. `check-tools`, which `build` also runs before any step, fails on a missing tool or a version mismatch. Homebrew's `pmtiles` reports `dev` and is accepted with a note on macOS only, since its version cannot be checked; on any other platform `bootstrap.sh` installs a release that reports its version, so `dev` there is a mismatch. The Python libraries the data layers use, pyosmium and Pillow, are `uv` dependencies, not tools ([ADR 0010](decisions.md)).
- **Validation and report:** `maqs/validate.py` reads each archive's PMTiles header and metadata directly (`maqs/pmtiles_header.py`, no tool output parsing), opens each SQLite file read-only, and `maqs/report.py` writes `build-report.json`. The formats and the validation rules are in [`docs/data-format.md`](data-format.md).
- **Release files:** `maqs manifest` (`maqs/manifest.py`) turns the build reports into `dist/manifest.json`. It reads `dist/<region>/build-report.json` for every region the release covers and `dist/base/build-report.json`, refuses a failed or incomplete build or a report that belongs to another directory, writes one entry per output with a URL pinned to the release tag, and validates the result against `config/schemas/manifest.schema.json` before writing it (`maqs/schemas.py`, on the `jsonschema` library). With `--previous`, the latest published manifest, it carries over the lower schema versions that manifest's own release built, the one-release window of the compatibility rule, and ends it after one release. The release workflow builds every region and the base packs, picks the previous manifest with `maqs previous-manifest`, runs `maqs manifest --previous`, checks the files with `maqs release-check` (`maqs/release.py`) and uploads the outputs and `manifest.json` to the `data-YYYY-MM` release; see [Data releases](#data-releases). `maqs check-config` validates `config/regions.yaml`, `config/sources.json` and, with `--manifest`, a manifest file. It is the CI gate on `sources.json`, which shipped apps read from `main`. The formats and the compatibility rule are in [`docs/data-format.md`](data-format.md), the reasons in [ADR 0012](decisions.md).
- **Directories:** `.cache/` for downloads and intermediate cuts, `dist/<region>/` for outputs, both gitignored. Nothing generated is committed except the Swift test fixtures, the `test` region's outputs under `Tests/MaqsTestSupport/Fixtures/` ([Swift package](#swift-package)). When `--dist` or `--cache` is omitted, both sit under the repository root (the parent of the `config/` directory holding `regions.yaml`), so a build run from `pipeline/` still writes to the root `dist/`. A path given explicitly is relative to the current directory.

### Tile layers

`versatiles convert --bbox …` reads the planet archives by HTTP range requests, so nothing downloads the planet. It adds `--bbox-border N` only when the region's `bbox_border` is above 0. The border keeps the map from going blank at the region's edge; the `test` fixture sets it to 0 to stay small ([ADR 0009](decisions.md)). The basemap is written with `--compress gzip` because MapLibre rejects brotli. Terrain is cut at z0–12 and left as stored. A base pack is the basemap over the union bbox of its regions, up to its `max_zoom`, with no border.

`terrain-hd` is opt-in. It reads Mapterhorn's zoom-6 regional archives (`6-<x>-<y>.pmtiles`) with `pmtiles extract`, after a `--dry-run` per archive to skip the ones with no tiles in the bbox, and joins several with `pmtiles merge`. A dry-run output it cannot parse fails the step instead of counting as zero tiles. An archive Mapterhorn does not publish answers HTTP 404, which makes `pmtiles extract` exit 1 and fails the step; the four archives under the launch regions exist. One live run across a zoom-6 boundary on 2026-10-15 exercised the dry-run, extract and merge path ([ADR 0009](decisions.md)). When the step ends, also on failure, it removes the part files of completed extracts and the merge temp file; a partial file left by an extract that itself fails stays until the next run overwrites it.

### Data layers

The three data layers read OSM data from the Geofabrik extract each region names, cut per region by `maqs/osm/extract.py`. Every stage writes into `.cache/`, and a file that exists is reused:

| Stage | Command | Cached as |
|---|---|---|
| Geofabrik extract | download `https://download.geofabrik.de/<extract>-latest.osm.pbf.md5`, then the `.osm.pbf` itself, and check its MD5 | `.cache/geofabrik/<extract>-latest.osm.pbf`, with `/` in the extract name replaced by `-` (`europe-italy-nord-est-latest.osm.pbf`), and its `.md5` |
| Hiking relations | `osmium tags-filter <extract> r/route=hiking` (referenced members are kept, osmium's default) | `.cache/geofabrik/<extract>-hiking.osm.pbf` |
| Region polygon | `osmium getid -r -t <extract> r<id>…` for the `clip.admin` relations, `osmium export -f geojsonseq --geometry-types=polygon`, then an Osmosis `.poly` with one section per ring and `!` before inner rings | `.cache/<region>/clip.poly` |
| Region extract | `osmium extract --polygon clip.poly -s complete_ways` on the Geofabrik extract (`--bbox` for a region without `clip.admin`) | `.cache/<region>/region.osm.pbf` |
| Region hiking extract | `osmium extract --polygon clip.poly -s smart -S types=route` on the hiking file (or `--bbox`) | `.cache/<region>/hiking.osm.pbf` |
| Places, roads | `osmium tags-filter` on the region extract: the place tags, and `w/highway=<curvature.highways>` | `.cache/<region>/places.osm.pbf`, `.cache/<region>/roads.osm.pbf` |

The download goes through `maqs/cache.py`: streamed to a `.part` file with the User-Agent `maqs-pipeline/<version> (+https://github.com/lucavallin/maqs)` and a 60-second timeout on the connection and on each read, renamed when complete; a network or HTTP error (a timeout, a reset, a body cut short) deletes the `.part` file and fails the step, and so does an MD5 mismatch. Each osmium cut and filter writes `<name>.tmp.osm.pbf` next to its target and renames it only when osmium succeeds; a failed run removes it, so a file under a cached name is always a complete one. The extract is downloaded once and never again, `--force` included: delete it to refresh. `maqs fetch --extract <name>` runs this download alone, for an extract `regions.yaml` names, and does nothing when the file is there; the release workflow fills its cache with it. `--force` rebuilds every cut and filter. The filtered files are cached by name alone, so after changing `curvature.highways` rebuild with `--force`. Several admin relations (`triveneto` lists three) become one `.poly` file with one section per ring, because `osmium extract --polygon` takes exactly one file. The `smart` strategy with `types=route` keeps every route relation that has a member in the region, with all its members, so a relation that crosses the region's border stays whole as far as the Geofabrik extract reaches; members outside the extract itself are reported missing. Each data step writes the extract's replication timestamp (`osmium fileinfo -g header.option.osmosis_replication_timestamp`) into its metadata row (`steps/data.py`, `metadata_for`).

- **Trails** (`maqs/trails/`): each source in `trails.sources` has an adapter under `trails/sources/` that turns its data into `TrailRecord`s (`trails/model.py`), the normalised record of [ADR 0006](decisions.md). `trails/merge.py` merges the sources by priority, `trails/step.py` samples the terrain, writes the SQLite file and the overlay. The only adapter is OSM (`trails/sources/osm.py`, pyosmium); the merge is exercised in tests with a synthetic second source. A new source is an adapter module, its name in `KNOWN_TRAIL_SOURCES` and in the step's source dispatch, and a source ADR; the merge, the schema and the overlay stay as they are.
- **Places** (`maqs/places/step.py`) and **curvature** (`maqs/curvature/`) read their filtered cut with pyosmium. `maqs/overlay.py` writes the GeoJSONSeq for the trails and places overlays next to the output, runs tippecanoe and removes the temporary file. `maqs/sqlite_out.py` holds the three schemas and the one writer.

Trails reads `<region>-terrain.v1.pmtiles` from the same output directory for ascent and descent (`maqs/pmtiles_reader.py` finds the tile, `maqs/osm/terrain_sampler.py` decodes it with Pillow), so terrain runs first; the default layers include it. The skip rule looks only at a step's own outputs: a trails file built in a run without terrain keeps null ascent and descent until it is rebuilt with `--force` once the terrain archive exists.

Known limit: a region with no trails, or no places, fails that step. tippecanoe refuses an empty input ("Did not read any valid geometries", exit 110, with tippecanoe 2.79.0), so no overlay is written. No configured region is affected.

The formats and formulas are in [`docs/data-format.md`](data-format.md); the constants and the measured counts and sizes are in [ADR 0011](decisions.md).

### Tests

`uv run pytest` runs without the external tools and without the network. An autouse fixture in `tests/conftest.py` makes `urllib.request.urlopen` raise in every test not marked `network`. OSM fixtures are written in code with pyosmium's `SimpleWriter` (`tests/osm_fixtures.py`): nodes, then ways, then relations, each by ascending id, the order osmium expects. The one `network` test (`tests/test_integration_network.py`, run with `--run-network`) builds the `test` region end to end against the live sources, into a temporary `dist` but with the repository-root `.cache/`, so the Geofabrik extract is downloaded once and reused. The `test` region has no `expect` block; the network test asserts its row counts instead.

### CI

`.github/workflows/pipeline.yml` runs on pushes to `main` and on pull requests, in both cases only when they touch `pipeline/`, `config/` or one of the three workflow files (`pipeline.yml`, `build-maps.yml`, `swift.yml`), and on manual dispatch. Both jobs run on `ubuntu-24.04`, not `ubuntu-latest`: the tool pins, the cached binaries and the Boost 1.83 runtime package were verified on that image, so moving to another one is a deliberate change.

- `unit`: `ruff check`, `ruff format --check` and `pytest`, without the external tools; time-boxed to 10 minutes.
- `smoke`: restores the tool binaries from a cache keyed by the pins, or runs `pipeline/bootstrap.sh` on a miss. It fetches the `.md5` of the `test` region's Geofabrik extract (`europe/italy/nord-est`) with `curl` and restores `.cache/geofabrik` from a cache keyed on that checksum (`geofabrik-nord-est-<md5>`, the key `build-maps.yml` uses too), so an unchanged extract is not downloaded again; Geofabrik rebuilds it daily. The cached directory also holds the derived hiking filter, which a cache hit reuses. The job runs `maqs check-tools`, builds the `test` region with the five default layers (`--dist` and `--cache` at the workspace root), and prints the report. It builds the base packs (`--region base`, today the 13 MB `triveneto` pack), because a manifest must list every configured base pack. It assembles a manifest from those two builds with `maqs manifest --release data-ci --regions test` and validates it with `maqs check-config --manifest`, which checks `regions.yaml` and `sources.json` as well; the `data-ci` tag exists only for this and is never published. It then runs the live network test, which builds the region again and fails the job unless all five steps validate, the basemap is gzip, z0–14 and more than 20 tiles, the terrain is WebP z0–12, the two together stay under 5,000,000 bytes, the trails overlay is MVT from z6, and the row counts fall within trails 6–20, places 15–45, segments 80–280 and corners 400–1,250. Last, it uploads `dist/test` and `dist/manifest.json` as the `test-region-fixtures` artifact, kept 7 days. With two paths, `upload-artifact` roots the artifact at their common parent, `dist/`, so it holds `manifest.json` and a `test/` directory with the report and the seven outputs: nine files. Before the manifest was added the artifact measured 3,390,450 bytes zipped (2026-10-15). It is for inspection: the Swift tests read committed fixtures instead ([ADR 0014](decisions.md)).

Measured on 2026-10-15, before the base-pack and manifest steps were added, with the tool cache hit: when the Geofabrik cache missed, the smoke job took 3 min 22 s, with 2 min 4 s for the test-region build (the 625 MB download included) and 39 s for the network test. With the Geofabrik cache hit, the job took about 2 min 6 s: 6 s to restore the extract, 55 s for the build and 40 s for the network test. A tool-cache miss adds about 2 min of bootstrap.

The data releases come from a second workflow, `build-maps.yml`, which runs monthly and on dispatch, never on pull requests ([Data releases](#data-releases)). The package has its own workflow, `swift.yml` ([Swift package](#swift-package)). All three workflows pin third-party actions to a full commit SHA with the version in a comment, and GitHub's own `actions/*` to a major tag; `pipeline/tests/test_workflows.py` checks the pins, the token scope, the main-branch gate and the order of the release steps, and `pipeline.yml` runs when any of the three workflows changes.

## Data releases

`.github/workflows/build-maps.yml` builds every region and publishes the month's `data-YYYY-MM` release. It runs at 03:00 UTC on the 1st of each month and on manual dispatch, with two optional inputs, `region` and `layers`. All three jobs run on `ubuntu-24.04`. The workflow has `contents: read`, and only `release` can write. Runs share one concurrency group with `cancel-in-progress: false`, so a run in progress is never cancelled. The reasons, the `gh` behaviour the workflow relies on and the measured runs are in [ADR 0013](decisions.md).

| Job | Runs | Does |
|---|---|---|
| `prepare` (15 min) | always | `maqs check-config`; refuses a `layers` input that is not comma-separated lowercase names; plans the run from `maqs regions --json`: the targets, the tag `data-YYYY-MM` for the current UTC month, whether the run is full, the layers; warms the Geofabrik cache |
| `build` (45 min per leg) | one leg per target, `fail-fast` off | fails under 6 GB of free disk; the tools, as in `pipeline.yml`; `maqs build --region <target> [--layers …]` with `--dist` and `--cache` at the workspace root; prints the build report; uploads `dist/<target>` as the artifact `dist-<target>` |
| `release` (60 min) | full runs on `main` whose legs all passed | assembles and checks the manifest, uploads, marks the release latest |

**Full and subset runs.** A run is full when both inputs are empty and it runs on `main`, as every cron run does. Its targets are every non-fixture region plus `base`, the base packs. A dispatch with `region` builds that one target: any configured region, the `test` fixture included, or `base`; an unknown id fails `prepare`. A dispatch with only `layers` builds those layers for every non-fixture region, without `base`. Both are subset runs: they upload their artifacts and skip `release`, so a subset run never assembles a manifest and never publishes. A dispatch on another branch (`gh workflow run build-maps.yml --ref <branch>`) is never full: `prepare` logs `not on main: build only`, the legs build the targets a full run would, and `release` is skipped, which its own `github.ref` condition also enforces.

**Cache and artifacts.**
- The Geofabrik extract sits in `.cache/geofabrik`, cached under `geofabrik-nord-est-<md5>` with the MD5 Geofabrik publishes, the same key as the smoke job in `pipeline.yml`. `prepare` restores it; on a miss `maqs fetch --extract europe/italy/nord-est` downloads and checks it, and the cache is saved when `prepare` ends. Each region leg restores it with `fail-on-cache-miss`, so the extract is downloaded at most once per run and never per leg. The `base` leg reads no OSM data and skips it. `prepare` fails if `regions.yaml` names any extract other than `europe/italy/nord-est`: the key and the `maqs fetch` call name that one, so a region from another extract also needs the workflow changed.
- The tool binaries come from a cache both workflows fill, keyed by the pins (`TOOLS_KEY`); on a miss the leg runs `pipeline/bootstrap.sh` and saves the cache.
- The artifact `dist-<target>` holds `dist/<target>/`, the outputs and `build-report.json`, kept 7 days. `release` downloads every `dist-*` into `artifacts/` and moves each to `dist/<target>/`, the layout `maqs manifest` reads.

**The release job**, in order:
1. Fetch the latest published manifest. `gh api repos/<repo>/releases --paginate`, its pages joined with `jq -s 'add'`, gives the release list, and `maqs previous-manifest` (`maqs/release.py`) prints the tag to download `manifest.json` from: the newest published `data-YYYY-MM` release that has one. When none has, it prints `none`, the run is a first release and `maqs manifest` gets no `--previous`. A newer release without a manifest is this run's own tag (repaired by this run) or an older orphan, both with a warning; when it is the newest and another month, the job fails until the owner re-runs that month or deletes it ([ADR 0013](decisions.md)). A `gh` error fails the job too.
2. `maqs manifest --release <tag> [--previous …]`, then `maqs check-config --manifest`. A full run has built every region and base pack the tag needs, so no `--regions` is passed.
3. `maqs release-check --dist dist --manifest dist/manifest.json [--previous …] --notes notes.md` (`maqs/release.py`): every file the manifest names under this release's tag must be in `dist/<label>/` with the manifest's bytes and SHA-256, unless the previous manifest names it under this tag with the same SHA-256. That file is already on the release, from the month's first run, and is not uploaded again. Asset names must be unique in the release. Entries carried from an older tag live on that release and are not checked here. It prints one `<label>/<file> <bytes>` line per file to upload, a total and the number of entries carried from earlier releases, and writes the release notes: each region with its layers' OSM timestamps, the base packs, the number of carried entries and the attribution.
4. `gh release create <tag> --target "$GITHUB_SHA" --latest=false --notes-file notes.md` if the release does not exist yet. The tag points at the commit the run built from.
5. `gh release upload <tag> dist/<label>/<file>… --clobber` with the paths step 3 printed, then `gh release upload <tag> dist/manifest.json --clobber`.
6. `gh release edit <tag> --latest --notes-file notes.md`, which also replaces the notes with this run's.
7. The carried count and the asset list go to the run summary.

Nothing is uploaded until steps 1–3 pass, and when a leg fails, `release` does not run at all.

**Re-runs.** `gh workflow run build-maps.yml` with no inputs rebuilds the current month. When the month's release exists, step 4 is skipped, same-named assets are deleted and re-uploaded, `manifest.json` last, and the release is marked latest. If it already was latest, the previous manifest is the month's own, and `maqs manifest` keeps every lower-version entry that manifest lists (the same-month rule in [`data-format.md`](data-format.md#compatibility-rule)). Nothing on an older release is touched, so carried entries stay online. On this month's release `--clobber` deletes and re-uploads same-named files, and when the run succeeds every file the new manifest names is present. A new month's release is created off latest and becomes latest only in step 6, so when that run fails, clients keep reading the previous month's manifest.

**What clients can rely on.** Phase 4 builds the client side on these guarantees:
- `manifest.json` is uploaded after every file it names, and a new month's release becomes latest only after its manifest is up.
- During a same-month re-run, or after one that failed midway, the manifest can name a file that is gone, because `--clobber` deletes an asset before it uploads the new one (a 404), or a file that is already the new build (a SHA-256 mismatch). If the manifest upload itself fails, the latest release has no `manifest.json` until a re-run in the same month, or until the owner deletes that release.
- In each of these cases the client keeps the data it has installed, never installs a file that fails its SHA-256, and re-fetches the manifest later.
- Nothing on an older release is touched, so carried entries stay online. When a run succeeds, every file the new manifest names is present.

## Swift package

The package `Maqs` is Swift 6 (tools version 6.2) for iOS 18 and macOS 15; `MaqsUI` draws only on iOS, because MapLibre's binary is iOS only ([ADR 0003](decisions.md)). Every target treats warnings as errors through `.treatAllWarnings(as: .error)`, with no `unsafeFlags`, so the package stays usable as a dependency. The decisions and the facts verified for this section are in [ADR 0014](decisions.md) for `MaqsCore`, [ADR 0015](decisions.md) for `MaqsTerrain`, [ADR 0016](decisions.md) for `MaqsData` and [ADR 0017](decisions.md) for `MaqsUI` and `MaqsPMTiles`.

| Product | State | Imports |
|---|---|---|
| `MaqsCore` | available | system frameworks only: Foundation, CryptoKit, Observation, Synchronization, os |
| `MaqsTerrain` | available | system frameworks: Foundation, CoreLocation, CoreGraphics, ImageIO, os; and `MaqsPMTiles` |
| `MaqsData` | available | system frameworks only: Foundation, SQLite3, CoreLocation, os |
| `MaqsUI` | available, draws on iOS only | MapLibre Native, the only module in `Sources/` that imports it; `MaqsCore` and `MaqsPMTiles`; Foundation, SwiftUI, UIKit, CoreLocation, Network, CryptoKit, Synchronization, os |

`MaqsPMTiles` is an internal target, not a product: the PMTiles v3 reader `MaqsTerrain` and `MaqsUI` share, with `package` access only. It imports Foundation, Compression and Synchronization.

Dependencies point one way: `MaqsUI` depends on `MaqsCore`, `MaqsPMTiles` and MapLibre (on iOS only), `MaqsTerrain` on `MaqsPMTiles`, and `MaqsCore`, `MaqsData` and `MaqsPMTiles` on no other module of the package. `MaqsTerrain` and `MaqsData` import nothing from `MaqsCore`: the app hands them the file URLs of an installed pack. For online terrain the app also builds an `OnlineTerrainSource`, `MaqsTerrain`'s own type, from `MaqsCore`'s `TileSource` ([Terrain](#terrain)). `MaqsUI` reads the online sources, the installed packs and the catalog from the app's `Maqs` itself, because every map needs them; it uses neither `MaqsData` nor `MaqsTerrain`, and a tap returns a region and a feature id for the app to look up in `MaqsData` ([Map](#map)). An app that needs only elevation links `MaqsTerrain` alone and never pulls in MapLibre.

Clients read two files from GitHub, neither through the REST API. `manifest.json` comes from `https://github.com/lucavallin/maqs/releases/latest/download/manifest.json`, and its tag-pinned URLs lead to the files it lists. `config/sources.json` comes from `https://raw.githubusercontent.com/lucavallin/maqs/main/config/sources.json`, cached, with a copy bundled in the package as the fallback. How a client picks the files it can read is the compatibility rule in [`docs/data-format.md`](data-format.md#compatibility-rule); what it can assume about a release while one is being published is under [Data releases](#data-releases).

### Discovery

`Maqs.refreshCatalog(policy:)` loads `manifest.json`. `.ifStale` returns the cached copy while it is younger than `catalogMaxAge` (24 hours by default). `.always` asks the server with `If-None-Match`, and a 304 only renews the fetch date. The package never fetches on a timer and never retries: a 429 is `ManifestError.rateLimited`, and the app decides when to try again. The manifest is decoded strictly, and every entry URL must be HTTPS on the manifest's own host. A rejected manifest, or one with an unknown `manifest_version`, leaves the cached one in place and sets `MaqsState.lastRefreshError`.

The catalog lists the regions and base packs with only the layers the app configured. For each layer it takes the newest entries whose `layer_schema_version` the package reads, the client half of the compatibility rule; a layer offered only in newer versions is `unreadable`. Each pack's status compares the installed SHA-256s with the release: `notInstalled`, `installed`, `updateAvailable` with the bytes an update downloads, or `partiallyInstalled` when the app's layer set grew since the install.

`refreshOnlineSources(policy:)` fetches `sources.json` with the same policy, conditional request and no retry, but it reports a failure only by throwing: it does not set `lastRefreshError` or change `MaqsState`, and the last good copy stays in use. `onlineSources` returns the cached copy, else the bundled one, and is `nil` when the app sets `onlineTiles` to false (the opt-out of ADR 0008); then no tile URL reaches `MaqsUI` or `MaqsTerrain`.

### Install

A pack moves through these `PackState`s:

```
notInstalled → queued → downloading → verifying → installed | failed
```

A pack is `queued` only while another pack's install runs. `cancelInstall(_:)` returns it to `installed` or `notInstalled`, whichever it was, and `failed` keeps whatever was installed before. An `install` after `cancelInstall` does not join the cancelled install: it is registered at once, so a second `cancelInstall` or a `remove` reaches it, and it takes its place in the line once the cancelled one has ended.

`install(_:)` runs one pack at a time, in call order. It fetches every file of each configured layer whose set of SHA-256s differs from the installed record, and nothing for a layer whose set matches. It downloads at most two files at once, checks each file's size and then its SHA-256, marks each verified file Protected Until First User Authentication, moves the files into content-addressed directories with `rename(2)` and writes `pack.json` last, also in that class. Readers trust only the files `pack.json` names, so a crash leaves the old pack or the new one, never a mix; the sweep in `Maqs.init` removes what an interrupted install left behind. Storage, under `Application Support/Maqs/`, excluded from backup:

```
manifest.json  manifest.meta.json             # cached manifest; its ETag and fetch date
sources.json   sources.meta.json
packs/region-<id>/pack.json                   # or base-<id>; readers trust only the files it names
packs/region-<id>/<layer>/<sha256>/<file>     # installed files, addressed by content
downloads/<sha256>-<file>                     # partial and completed downloads
downloads/<sha256>-<file>.resume              # resume data
```

**Background downloads.** On iOS the app sets `backgroundSessionIdentifier` and forwards `application(_:handleEventsForBackgroundURLSession:completionHandler:)` to `Maqs.handleEventsForBackgroundURLSession(identifier:completionHandler:)`. The package calls the handler on the main thread once the session has delivered its events. A download goes on while the app is suspended or not running, but the package does not remember which packs the user asked for: after a relaunch the app calls `install(_:)` again for them, and that call joins a transfer still running or reuses a finished file after a size and hash check, instead of downloading it again. Without an identifier (macOS, tests) the session is a foreground one and downloads last as long as the process. A process creates one `Maqs`.

**Reading installed files.** An update deletes the files it replaced at once. Read `installedPack(_:)` again after `install` returns rather than keeping URLs from an earlier result: a file that was not opened yet may be gone. A PMTiles archive that `MaqsTerrain` already holds open stays readable until it is closed; a SQLite file does not (below). `MaqsData` opens its SQLite files read-only and immutable, so no `-wal` or `-shm` file appears for the sweep to delete. Replacing or deleting a file that is open makes libsqlite3 fail later reads, so after every install, update or removal the app passes the current URLs to `setFiles(_:)` ([MaqsData](#data)).

### Terrain

`MaqsTerrain` gives the elevation at a point, along a route, over a grid and along a great-circle profile, and tells which of a list of targets an observer can see. One `actor Terrain` owns its archives, its tile cache and its online state. The app creates it from a `TerrainConfiguration`: the terrain files of its installed packs (`terrain` and `terrain-hd`, in any order), an optional `OnlineTerrainSource` and a User-Agent that names the app. After an install, an update or a removal it reads `installedPack(_:)` again and passes the new URLs to `setArchives(_:)`.

**Sources.** For each tile a call needs, `Terrain` tries the local archives first, the one with the highest maximum zoom first, and then the online source. Where a local archive covers a point at the zoom the call needs, the call makes no online request for it, so inside an installed region a call needs no network; a look from inside one fetches online only the ground beyond the pack's border. Point and route samples read the finest zoom a source has (z13 under a `terrain-hd` archive, z12 elsewhere), a grid reads the coarsest zoom whose pixel is at most half a cell, and profiles and visibility read coarser tiles farther out, by default z12 to 10 km, z11 to 30 km, z10 to 40 km and z9 beyond. Every sample follows the rule in [`data-format.md`](data-format.md#elevation-sampling).

**Results.** Missing data is a value, `ElevationSample.missing` with the reason `noData`, `rateLimited`, `networkFailure` or `requestCap`, so a route keeps its local values when some online tiles fail. A damaged archive throws `PMTilesError` or `TerrainError`; one that fails to open is also logged with its file name. `visibility(of:from:options:)` returns one `Visibility` per target, in input order: `visible` with the distance, bearing and elevation angle; `hidden` with where the ground blocks the line; `unknown` with which height is missing and why; or `outOfRange`. Ground hides a target only when it clears the sight line by more than a margin, and missing ground never makes a target visible.

**Online path.** Each `Terrain` has one `URLSession`, made from a copy of the configuration, with its own `URLCache` (`diskCacheBytes`, 64 MiB by default, under `Caches/Maqs/terrain-tiles`) and `.useProtocolCachePolicy`. The provider's `Cache-Control` decides, so a repeated look within six hours sends no request. Every request carries the app's User-Agent followed by `Maqs/<version>`, and none carries a header that disables caching. At most four requests run at once, a tile is requested once however many callers wait for it, and a tile whose callers have all been cancelled before its request goes out is not requested. A 429 pauses every online request for 60 s, twice as long after each further 429 up to 15 minutes, and during the pause online tiles are `rateLimited`. One call fetches at most 128 tiles online. Decoded tiles from every source share one LRU bounded by `memoryCacheBytes`, 64 MiB by default, and a call reads its tiles in batches that fit that bound, so it holds the cache and one batch at most.

**Privacy.** A tile request carries tile coordinates, not the position. One tile gives away an area its own size: about 6.8 km across at z12 at 46° N, twice that at each coarser zoom. A full look requests a ring of tiles centred on the observer, and the set as a whole places the observer within about 500 m by a rough estimate, or within about 1 km from its z12 tiles alone. An app with a strict privacy stance sets `onlineTiles` to false; `onlineSources` is then nil, the app builds no online source and `MaqsTerrain` sends nothing.

**From `TileSource` to `OnlineTerrainSource`.** The app copies five values from the first terrain entry of `Maqs.onlineSources`:

| `TileSource` (`MaqsCore`) | `OnlineTerrainSource` (`MaqsTerrain`) |
|---|---|
| `tiles` | `tiles` |
| `format` | `format` |
| `tileSize`, always set for a terrain source | `tileSize` |
| `minZoom`, `maxZoom` | `minZoom`, `maxZoom` |

`OnlineTerrainSource` checks them again: an HTTPS template with `{z}`, `{x}` and `{y}` outside its host and port, `webp` or `png`, 256 or 512 px, zooms from 0 to 22. The attribution stays in `TileSource`, for the app to show.

### Data

`MaqsData` answers questions about the trails, places and curvature files of installed regions, offline and read-only. It has three readers, one `actor` per layer: `Trails`, `Places` and `Roads`. The app creates each from the file URLs of its installed packs (`InstalledFile.url` from `MaqsCore`; `MaqsData` imports nothing from it) and calls `setFiles(_:)` after every install, update or removal. Several files of one layer are read together, a record found in two is returned once and the first file wins, and with no files every query is empty. `MaqsData` makes no network request. A trail outside the installed regions cannot be found, because no online source of trail data exists.

**Opening.** A file is opened by URI with `immutable=1` and checked before use: one `metadata` row, the reader's layer, `schema_version` 1 and the tables and columns it reads. A file that fails is a typed `QueryError` naming it by its last path component. A read failure later, such as a file replaced under an open connection or one under Complete data protection while the phone is locked, is `unreadable`.

**Trails.** `search(_:near:difficulty:limit:)` returns summaries in three groups: an exact `ref`, `ref_rei` or `name`; a number inside a `ref` (`926` finds `926A` and `E926`); then full-text search, with every word quoted. `trail(_:)` and `trail(region:featureID:)` return the record with its path, one array per leg, and its `geometry_status`.

**Places.** `places(in: BearingCone, kinds:limit:)` returns the places inside a cone from an origin, nearest first, each with its distance, bearing and offset. The app maps them to `SightTarget`s for `MaqsTerrain`'s `visibility(of:from:)`. `places(in: QueryArea, ...)` returns the highest `rank_score` in a box.

**Roads.** `segments(near:within:limit:)` returns the road segments around a position for the app to match against. `cornersAhead(from:distance:)` walks on from the matched segment, direction and position, follows the junctions it meets (a segment's ends and the `junctions` table) and reports the corners ahead. At a fork it takes the likeliest branch and marks the fork and the corners after it; the rule, the one-way handling and the walk's other details are in [ADR 0016](decisions.md) and [`data-format.md`](data-format.md#curvature-layer_schema_version-1). Files built before the `junctions` table (`data-2026-10`) have end-node links only. [`data-format.md`](data-format.md#curvature-layer_schema_version-1) has the tables. `Curvature.analyze` applies the same corner formula to a list of coordinates.

ADR 0016 has the rules in full and the measurements.

### Map

`MaqsUI` is the map. `MaqsMap`, an observable model, is the one object per screen: it holds what the app wants drawn and reports what the map does. `MaqsMapView` shows it, and `MapAttributionView` shows its credits. MapLibre Native draws, but no public type is a MapLibre type, and every MapLibre call runs on the main actor in the view's coordinator. The decisions, the spike and the verified MapLibre facts are in [ADR 0017](decisions.md).

**Switching.** Inside an installed region the map draws from the downloaded files, even with signal. Outside every region it streams the first `sources.json` source of each layer when there is signal; with none it shows what MapLibre's ambient cache kept from earlier viewing, so a place never seen stays blank. Hillshade follows the same rules. The style has one `basemap` and one `terrain` source whose tile URLs are the provider's, and the tile gateway decides where each tile comes from, so where local meets online there is no seam and no label drawn twice. The map draws only what the app configured in `Maqs`: `MaqsMap.init` throws `MapError.basemapNotConfigured` without `.basemap`, hillshade needs `.terrain` and `showsHillshade`, and the overlays need `.trails` and `.places` configured, installed and turned on in `overlays`.

**The tile gateway.** `TileGateway` is a `URLProtocol` that `MaqsMap.init` puts first in MapLibre's own `sessionConfiguration.protocolClasses`, once per process, together with MapLibre's User-Agent. MapLibre builds its session when the first `MLNMapView` is created and never reads the configuration again, so the first `MaqsMap` must exist before any map view of the process. The decisions are made in `GatewayState`, one lock-protected value that every map of the process shares, because MapLibre calls the protocol on a background thread. A tile of the `basemap` or `terrain` template is answered in this order:

1. An installed region whose archives of that layer cover the tile (by their bounds, or by the region's catalog box when it has no archive of the layer) answers 200 with the tile's inflated bytes, or 204 when it has no such tile. Nothing inside a region goes online, even for a layer the region lacks. When several regions cover a tile, the archive with the highest maximum zoom wins, then the newest data date, then the pack id.
2. Otherwise the network answers, through the gateway's own `URLSession`: no `URLCache`, a 15 s timeout, MapLibre's request with its conditional headers, the app's User-Agent on every request, nothing that disables caching, and redirects followed only to the same scheme, host and port. The response goes back with the provider's headers, less `Content-Encoding` and `Content-Length`.
3. When the network cannot answer (the device is offline, a 429, a connection failure or a timeout, a TLS failure such as a captive portal's certificate, a running pause, `onlineTiles` false, or no online source), a base pack that covers the tile answers, 200 or 204. With none the request fails as not connected, and MapLibre retries it with backoff while it shows what it cached. While the device is offline the gateway skips the network at once.

The gateway's own answers carry no `Cache-Control` and no `Expires`, so MapLibre asks again on every load, never on a timer, and still draws its cached copy offline. With online tiles off, the style's sources name `https://maqs.invalid/basemap/{z}/{x}/{y}` and `https://maqs.invalid/terrain/{z}/{x}/{y}`, a reserved host the gateway claims and never sends to. The templates come from what the whole `Maqs` says (the online sources and the configured layers), never from one map's hillshade switch, and the gateway keeps claiming every template set it had earlier in the process: such a tile is served by its tile id, and online only through the current template. Any other URL passes through untouched, and a malformed tile URL never reaches an archive.

**The pause.** A 429 stops every online tile request for 60 s, each further 429 doubles the pause up to 900 s, and the first success after a pause sets it back to 60 s. A 429 or a success during a pause changes nothing. Meanwhile tiles take step 3. `onlineTilesPaused` reports the pause; the map reads it from the gateway every 5 s, so it can trail the pause by up to 5 s, and while a map exists the main actor wakes that often. The pause is the map's own: `MaqsTerrain` keeps a separate one ([Terrain](#terrain)).

**Connectivity, packs and the offer.** `NWPathMonitor` sets `connectivity`, and the map reads the packs only after its first report, so the gateway knows whether the device is offline before the first tile. The map then observes `maqs.state.packs` and the catalog. When installed files change, it reads `installedPack(_:)` for every pack, the headers of archives it has not read yet (off the main actor) and `onlineSources`, hands the gateway the new list and publishes new light and dark styles; download progress reads nothing. A region covers its catalog `bbox`, or the union of its archive bounds when the catalog lacks it. Base packs give their basemap only, `terrain-hd` files are not used for hillshade, and an archive that cannot be opened is logged and left out, so its region answers that layer empty. Overlays get new sources with the new file URLs. Tiles MapLibre already holds stay until it asks for them again, and an archive the gateway has open stays readable after its file is deleted. A refreshed `sources.json` takes effect at the next pack change or in a new `MaqsMap`. `uninstalledRegion` is recomputed when the camera settles and when the packs or the catalog change: it is `nil` when an installed region (installed, update available or partially installed, or installed according to the packs while the catalog catches up) covers the map's centre, and otherwise the smallest catalog region whose box contains the centre and that is neither installed nor queued nor downloading. Base packs are never offered.

**Style contract.** An app passes its own style JSON as `MapStyle.custom(light:dark:)`; the package's muted style is `.default`. A style needs a vector source named `basemap` (Shortbread 1.0) and a `layers` array, and for hillshade a raster-dem source named `terrain`. `MaqsUI` sets their `tiles`, zoom range, `tileSize` and `attribution`, sets `encoding: terrarium` on `terrain`, drops a `url` (MapLibre would prefer it to `tiles`), and removes `terrain` and its layers when hillshade is off. It sets `glyphs` and `sprite` to the bundled copies whatever the style says, so a style uses the font stacks `noto_sans_regular` and `noto_sans_bold` (glyph ranges 0–1023 and 8192–8447) and the icon names of the bundled `base` sprite. Source and layer ids starting with `maqs-` belong to the package; a style that uses one is `MapError.invalidStyle`, as is one without `basemap`. A layer with `metadata: {"maqs:poi-key": "<OSM key>"}`, such as `amenity` or `tourism`, is a point-of-interest layer: hidden unless `MapConfiguration.pointsOfInterest` lists a `PointOfInterest` with that key, and then filtered to the values listed. A label whose `text-field` reads `name` reads `name_<language>` first, for `labelLanguage` or the device's language. Both styles are assembled at once, and the view swaps them with the colour scheme; the sources keep their ids, so a swap asks for no tile again. When the app's style is invalid or MapLibre fails to load a style, `lastError` says so and the map keeps drawing the last style that built, still following the packs.

**Bundled assets.** `Sources/MaqsUI/MapAssets/` holds the glyphs, the sprite, the two default styles and `LICENSES.md`. `scripts/update-map-assets.sh` downloads the pinned VersaTiles releases, checks their SHA-256, only extracts them, and writes everything there except `LICENSES.md`, which is written by hand. The default styles are VersaTiles' `muted-terrain` and `muted-dark-terrain`, transformed by `pipeline/src/maqs/map_style.py`: source, glyph and sprite URLs become tokens the assembler fills in, the colours below are swapped in, point-of-interest layers are marked and hidden, and 3D terrain, sky and globe are dropped. A test checks that the committed styles name no remote URL and only bundled font stacks and glyph ranges.

#### Design rules

The look follows the package's design rules for maps. The colours, light and dark:

| Colour | Light | Dark | Used for |
|---|---|---|---|
| Base | `#EEF2F7` | `#191F28` | the map's background |
| Green | `#D0EEE9` | `#14282B` | forest, grass, park, garden and vegetation, each with its own opacity |
| Water | `#C1E5F6` | `#122442` | water areas and lines |
| Road | `#FFFFFF` | `#2E343E` | street lines |
| Casing | `#FFFFFF` | `#191F28` | under solid lines and grey trails; the halo of labels |
| Casing edge | `#101620` at 25 %, 9 pt | none | a thin edge under the light casing |
| Grey | `#8A8F96` | `#737980` | solid lines that are not active, grey trails, hidden markers |
| Hidden line | `rgba(16,22,32,0.5)` | `rgba(230,237,243,0.5)` | hidden lines |
| Label | `#101620` | `#E6EDF3` | marker and place labels |
| Place marker | `#101620`, white pictogram | `#2E343E`, `#E6EDF3` pictogram | the places overlay's markers |
| Location | `#1C6CF7` | `#61D0FF` | the user's location, never the accent |

The accent is the app's (`MapConfiguration.accent`). Hillshade keeps VersaTiles' values in light; in dark its highlight is `rgba(255,255,255,0.4)` and its shadow `rgba(0,0,0,0.6)`. Every other base layer keeps VersaTiles' colours.

- **Lines.** The one line whose id is `activeLineID` is the accent, 5 pt. Every other solid line is grey, 4 pt. Both lie on an 8 pt casing. Hidden lines are 3 pt, dashed 4 pt on and 5 pt off (`line-dasharray` `[1.333, 1.667]`), with no casing, under the solid ones. On the dark style a solid line with `glows` gets the accent at 60 % opacity, 12 pt wide and blurred by 6, under its casing. Caps and joins are round.
- **Markers.** A 30 pt circle with a 2 pt white ring and a shadow (0, 1, 3 at 25 % black), the app's content inside: a dot, a count, a photo, a pictogram on a fill, or a trail number on red. The selected marker is drawn 1.25× with a 4 pt accent halo at 35 % opacity, in its own layer above the others; one is selected at a time. A hidden marker is a grey disc inside the white ring, with a white glyph or a photo faded to grey. Labels are Noto Sans Bold 13 under the marker, with a 2 pt halo in the casing colour, and give way to other labels; icons may overlap. Taps count in a 44 pt square. The user's location is MapLibre's puck in the location blue, above every layer, so a selected marker under the user sits below it.
- **Trails overlay.** Grey 4 pt on an 8 pt casing and, along the line, the trail-number plate: red-white-red with the `ref` (Noto Sans Bold 11, `#101620`), the one mark on the map that is not round. Both start at zoom 11. The trail in `selectedOverlayFeature` is the accent, 5 pt, at every zoom.
- **Places overlay.** Peaks, volcanoes, saddles, passes, huts and shelters are 20 pt round markers, ring included, with a pictogram per kind and the name under them (Noto Sans Bold 13, dropped where it has no room). Villages, hamlets and isolated dwellings are a name only. Higher `rank_score` places first.
- **Points of interest** are off unless the app turns a kind on. There is no satellite imagery.

A solid `MapLine` that is not active looks exactly like an overlay trail, grey on a casing. An app that draws its own solid lines over the trails overlay may want the overlay off while they show, as the demo does for its sight line, or a style of its own.

**Layer order.** From the bottom: the base style's layers up to its first symbol layer; then every overlay layer, in this order: the trail lines (casing, grey, selected) of every region, the settlement names, the trail plates, the place markers; then the base style's symbol layers, its labels; then the app's content: `maqs-lines-hidden`, `maqs-lines-casing-edge` (light) or `maqs-lines-glow` (dark), `maqs-lines-casing`, `maqs-lines-solid`, `maqs-lines-active`, `maqs-markers` and `maqs-markers-selected`. The overlays sit under the base map's labels so that place and road names stay readable over the trails and the base map's labels, towns included, win placement over plates and place markers; a tap on a base map label therefore finds no overlay place. The app's lines and markers draw above everything. A base style with no symbol layer gets the overlays after its last layer. Overlay sources are `maqs-trails-<region>` and `maqs-places-<region>`. Each overlay layer id is its source id plus one word, `-casing`, `-line`, `-selected` and `-plate` for trails and `-names` and `-markers` for places, so no region id can make two layer ids equal.

**Content.** Lines and markers are two GeoJSON sources, `maqs-lines` and `maqs-markers`. Changing `lines`, `markers` or a selection replaces their data without a style load, so a track that grows by a point is cheap. A style load, including the light and dark swap and loads MapLibre starts itself, clears everything set at run time, so after each one the map sets the lines, the markers, their images, the place and plate images and the overlay selection again. Marker images are drawn once per distinct look and named from a SHA-256 of the content, the variant, the colour scheme and the accent. A photo or a pictogram counts by its PNG data, encoded and hashed once per `UIImage` instance; one with no PNG data gets a name of its own, so two such pictures never share an image. Two lines or markers with the same id: the last wins. An `activeLineID` or `selectedMarkerID` that names nothing marks nothing. Points that are not finite or off the earth are dropped, and a line with fewer than two points is not drawn.

**Camera, location and taps.** `camera` updates when the camera settles, not while it moves. `follow(_:)` maps to MapLibre's tracking modes: a pan, `show` or hiding the location drops to `.none`, and turning north or rotating turns heading or course into `.position`. While the camera follows, `setPitch(_:)` (kept within 0–60°) and `resetNorth()` act at once, because the next location would cut an animation short. `contentInsets` is the room the app's chrome takes, exactly: the map adds no safe area, and leading and trailing follow SwiftUI's layout direction. `show(_:)` fits a box inside the insets with no padding of its own. A `show` made before a view with a size shows the map is kept and applied at its first layout; a later `show` replaces it and following cancels it. Input that is not finite or off the earth is ignored and logged at debug level, because MapLibre would crash on it. The map never asks for location permission (the [README](../README.md#swift-package) says what the app does): `.system` shows MapLibre's own location once the app has permission, and again when the user allows it after denying it; `.provided` shows what the app passes to `provide(_:)`, and then `.heading` follows the position only. `onTap` gets the coordinate and what lies in the 44 pt square around the touch, topmost first and each once: the app's markers and lines, and the overlays' trails and places as an `OverlayFeature`, the region and feature id `MaqsData`'s `trail(region:featureID:)` and `place(region:featureID:)` take. Overlapping regions give one hit each. A tap on the user's location is reported like any other, with no hit for it, and a double tap or a tap-and-drag zoom is not reported. MapLibre's compass, logo, attribution button and scale bar are hidden, from VoiceOver too.

**Credits.** `credits` is the union, without duplicates, of the credits of every layer being drawn: the basemap always, terrain while hillshade draws, trails and places while their overlays show. A layer drawn from the online source carries that source's `sources.json` attribution; a layer an installed pack provides carries the manifest's `Catalog.attribution` entries for it, with their pages. The credits follow every style the map builds and every catalog change. A drawn layer with no credit at all is logged at error level when it loses its credit, and again only after it had one, or was not drawn, in between; the known credits are still published. An offline-only map (`onlineTiles` false) draws its basemap and hillshade with no source to credit where no installed pack provides them, so it logs this line there; that is expected. `MapAttributionView` shows the first credit beside an info button that expands the list in place, each credit with a page as a link. The button's touch area is at least 44 × 44 pt, it is labelled "Map data credits" with the value "Collapsed" or "Expanded", the text is `caption2` and grows with Dynamic Type, wrapped lines start at the leading edge, and the view sets no size, padding or background, so the app places it in its own chrome.

**Logging.** `os.Logger`, category `ui`: style loads and failures, the pack ids on every change, the gateway's counts of the last minute whenever any changed (local, empty, online, base, failed, stale template), each 429 with its tile coordinates `privacy: .private`, the start and end of each pause, an unreadable archive once by file name, and a drawn layer without credit. No URL, tile content or position is logged.

**Not verified.** Everything above ran on the iOS Simulator; a real device has not shown the map yet, so the airplane-mode walk, the offline banner (the simulator shares the Mac's network) and the location prompt on a device are open. CI's Xcode 26.6 has not built the MapLibre-specific code, the demo project or the view tests' accessibility switch yet; the branch's first CI run checks them. The hillshade shows straight seams at some tile borders, and their cause is not known ([ADR 0017](decisions.md)).

### Tests and CI

`swift test` runs the five test targets, `MaqsUITests`, `MaqsTerrainTests`, `MaqsPMTilesTests`, `MaqsDataTests` and `MaqsCoreTests`, against committed fixtures, the `test` region's data files and the `data-ci` manifest in `Tests/MaqsTestSupport/Fixtures/`. Each target prints its own `Test run with N tests` line. The test-only target `MaqsTestSupport` serves the fixtures, together with `StubServer`, a `URLProtocol` stub, so no test touches the network, and a writer for small PMTiles archives, which is why it depends on `MaqsPMTiles`.

`MaqsUITests` has two kinds of suites. The pure ones (style assembly, tile templates and routing, the pause, the gateway's `URLProtocol`, credits, the download offer, lines and markers as GeoJSON) run on macOS and on the simulator. The map suites need MapLibre and run only on the simulator, inside the package's test bundle: each test creates a key `UIWindow` and shows the map in it, because a map view in no window loads nothing. They install the `test` region through `MaqsCore` from the fixtures over a `StubServer`, and a tripwire in MapLibre's session fails any request the gateway does not take. Every suite that touches the process-wide gateway or MapLibre's session is nested in one serialized parent suite, `SharedGatewaySuite`. The headline test installs the `test` region, makes every network request fail and checks that the map draws with no request reaching the stub. The demo app has no tests; the [README](../README.md#demo-app) has its manual walk. `scripts/update-fixtures.sh` rebuilds the `test` region and the base packs with the pipeline, copies the data files and the manifest into the fixtures, copies `config/sources.json` to `Sources/MaqsCore/Resources/sources.json`, runs `scripts/update-terrain-golden.sh`, and fails above 8 MB. That script writes `Fixtures/test/terrain-golden.json` from the committed terrain fixture with the pipeline's reader and sampler (`uv run python -m maqs.terrain_golden`), so the terrain tests compare the Swift reader and sampler with the pipeline's. `scripts/update-data-golden.sh` does the same for the data layers: it writes `Fixtures/test/data-golden.json` (`uv run python -m maqs.data_golden`) from the committed fixtures with the pipeline's polyline decoder and corner scoring, and `update-fixtures.sh` runs it too.

`.github/workflows/swift.yml` runs on pushes to `main` and on pull requests that touch the package (`Package.swift`, `Package.resolved`, `Sources/`, `Tests/`, `Examples/`, the fixtures script, `scripts/update-map-assets.sh`, `config/sources.json` or the workflow), and on dispatch. It has `contents: read` and three jobs:

- `guards` (`ubuntu-24.04`): `import MapLibre` appears only under `Sources/MaqsUI/` and in its test target, `Tests/MaqsUITests/`, whose map suites need it; the bundled `sources.json` equals `config/sources.json` (`cmp`); `TerrainVersion.string` in `MaqsTerrain` equals `MaqsVersion.string` in `MaqsCore`, since both go into the User-Agent; the fixtures stay at or under 8,192 KB; git tracks no `.pmtiles`, `.sqlite` or `.pbf` outside the fixtures, except the bundled glyphs' `.pbf` files under `Sources/MaqsUI/MapAssets/glyphs/`, which `scripts/update-map-assets.sh` regenerates (ADR 0017).
- `macos` (`macos-latest`): `swift build` and `swift test`.
- `ios-simulator` (`macos-latest`): picks the scheme from `xcodebuild -list -json` (`Maqs-Package`, the name Xcode gives a package with several library products, as this one has, else `Maqs`), runs `xcodebuild test` on an `iPhone 17` simulator with `-collect-test-diagnostics never` (a test that hits its time limit would otherwise add about ten minutes of diagnostics), and passes only when the log has no `": error:"` line and a passing `Test run with N tests` line. It then builds the demo app for the simulator with signing off, and fails on any `": error:"` line or a non-zero exit.
